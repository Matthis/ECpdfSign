- (event) create run; interactive; input rich (in-chat), extract directly without elicitation; slug ecpdfsign given by user
- (direction) Why: vision/pain — sign PDFs (image signature) on own machine without uploading documents to cloud signing services
- (capability) CAP-1: user opens a local PDF and sees a page preview; multi-page PDFs supported, user selects which page is shown/signed
- (capability) CAP-2: user loads a signature stored as PNG; alpha transparency preserved in preview and output
- (capability) CAP-3: user places the signature on the selected page by mouse drag and scales it by mouse
- (capability) CAP-4: optional place/date text (e.g. 'München, 17.10.2026'): date prefilled with today and editable, place free text; placed like the signature, default position beside or below it; can be omitted entirely (either part or both)
- (capability) CAP-5: user saves result as a new PDF; original file stays unchanged
- (constraint) fully local: no network access, no cloud services, no telemetry — rules out remote fonts/CDNs and online services
- (constraint) targets Windows 11 and macOS desktop
- (constraint) stack fixed by user: Tauri 2, vanilla TypeScript (no framework), pdf.js for rendering, pdf-lib for writing
- (constraint) original PDF never written: save target must differ from source path; overwrite of source refused
- (constraint) PDFs are untrusted input: CSP (currently null in tauri.conf.json) must be locked down before shipping; no remote origins
- (constraint) brownfield: repo is unmodified create-tauri-app vanilla-ts template (sample greet command only); keep lib/bin split
- (decision) non-goals: cryptographic/qualified signatures (PAdES); cloud features; any PDF editing beyond inserting signature and place/date text
- (decision) success signal: multi-page PDF signed on page >1 with transparent PNG + place/date text, saved as new file, opens correctly in Acrobat Reader and macOS Preview at the placed position; original byte-identical; no network traffic
- (assumption) date format DD.MM.YYYY, text as '<place>, <date>' per user example
- (assumption) UI language German (user and example are German)
- (assumption) signature scaling keeps aspect ratio
- (assumption) place/date text is moved and resized like the signature (input says 'placed like the signature')
- (assumption) one signature placement and one text block per save; additional placements not required
- (assumption) signature creation (drawing/scanning in-app) out of scope; user supplies the PNG file
- (assumption) output position must match preview on any page size, page rotation and non-zero MediaBox/CropBox origin (implied by WYSIWYG placement)
- (question) multiple signatures/pages per document (e.g. initials on every page) needed in v1?
- (question) encrypted/password-protected PDFs: support, or reject with message?
- (question) PDFs already carrying digital signatures: pdf-lib full rewrite invalidates them — warn, block, or ignore?
- (question) place text font: pdf-lib standard fonts are WinAnsi-only (ü ok, e.g. Ł/ő not) — embed a bundled Unicode font?
- (question) macOS distribution: code signing/notarization and Windows code signing in scope, or unsigned builds acceptable?
